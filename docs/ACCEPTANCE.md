## 发布前要实际完成的流程

在 Windows 和 macOS 分别记录系统版本、硬件型号、固件、虚拟音频设备及测试结果：

1. 首次启动、权限缺失提示、配对、选择型号；错误型号、未配对、设备休眠和不支持的驱动应给出明确失败原因。
2. 同型号两台设备间切换，只接收选中设备的事件。拔掉、断开和重连不能留下按住的快捷键或开启的录音。
3. 单击、双击、长按和没有映射的按键；统计应按实际按下次数计数。
4. 按住说话、松开结束、较长语音分段、快速连按、退出和异常恢复；检查实际音频时长以及原麦克风恢复。
5. 回眸默认关闭；开启后的中文、英文、选区替换；密码框、不支持的输入框和同时手动输入应跳过；搜索、分页、导出、删除后不可再检索。
6. MCP 未授权不能读；授权后只读；关闭或撤销后，正在运行的客户端下一次请求被拒绝。
7. 导入第二份有效型号包，核对外形、控件、手势和独立配置；无效字段、越界图片、重复 ID/usage 和未实现能力应被拒绝。
8. 安装、升级、退出、卸载；不得携带个人日志、授权码、绝对开发路径或旧产品的在线更新入口。

## 硬件贡献的边界

当前只有 `xiaomi-atvv-v1` 适配器。导入型号文件是候选配置，不是兼容性证书。Windows HID 还要求系统驱动指纹匹配；macOS 可按型号包的传输标识发现设备，并核对实际 DIS 型号及 ATVV 能力。其他协议、不同 HID 报告格式或编码仍需增加适配器，并在真实设备上完成以上流程。

## 功能对齐范围

| 功能 | Windows / macOS 共同实现 | 尚待实测或仍有差异 |
| --- | --- | --- |
| 统计 | 今天、本周、全部记录；按日明细；按键次数、实际音频时长、会话数 | 真实按键及音频回调的端到端计数 |
| 回眸 | 默认关闭、仅本次新增文字；关键词、应用、日期筛选；分页、复制、JSON 导出、删除 | 不同输入法和目标编辑器的辅助功能行为 |
| MCP | 同一 Helper、共享格式、四个只读工具、逐客户端授权及即时撤销 | 用户实际 Agent 客户端连接 |
| 型号包 | 同一 JSON、外形图片、热点、自定义按键 ID、手势能力与导入校验 | 第二种真实硬件；Mac 的 HID 与蓝牙档案关联及多设备行为 |
| 按键动作 | 单击、双击、长按、自定义快捷键 | Windows 保留 Codex/Claude 模板，Mac 保留原生系统动作；动作目录尚未逐项对齐 |
| 安装与设备 | 两端开发包均能生成；Windows 注册系统卸载入口，保留个人数据且拒绝路径重定向 | 实际安装/升级/卸载待验收；Mac 未签发公证发行包 |

macOS 上游的 RC001、电量等能力没有全部移植到 Windows；Siri Remote、手机/手表等可选私有包不在公开源码交付范围。当前共同功能已实现并通过自动检查，完整功能一致和公开发布的条件尚未满足。

两端源码中已有新功能的实现，不代表两端功能一致已经验收通过。GitHub 仓库应保持私有，直至这些未完成项有实际证据。
